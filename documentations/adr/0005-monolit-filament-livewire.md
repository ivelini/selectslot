# 0005. Монолит Laravel: Filament-админка и Livewire-сайт, без внешнего API

- **Статус:** Accepted
- **Дата:** 2026-09-04
- **Связанные ADR:** —

## Контекст
Сервис — одна точка шиномонтажа, два интерфейса: публичный сайт записи и админка. Встал вопрос архитектуры: монолит или разделение (микросервисы, SPA + API).

## Решение
Монолит на Laravel: админка — Filament, публичный сайт записи — самостоятельный сайт на Livewire в том же приложении. Внешнего REST API в v1 нет; каналы записи (сайт, админка) используют единые доменные Action/Service.

## Почему (альтернативы)
Микросервисы для одной точки — распределённые транзакции вокруг гонки «закрытие слота vs запись» (НФ-1) в худшем виде; пользы нет. SPA + API дали бы внешний контракт, но потребителей нет; Filament и Livewire — один стек (Livewire 3), одна сессия, один деплой. Цена: сайт связан с монолитом — при выносе сайта на отдельный хостинг или встраивании на сторонний ресурс потребуется выделение API.

## Последствия
Вся логика записи в одном месте — НФ-4 выполняется естественно. Scramble/OpenAPI отложены до появления внешнего канала. Пересмотрим при канале вне PHP-стека (телеграм-бот, мобильное приложение) — тогда выделим API-слой поверх тех же Action.
