# 0007. Прайс: полный набор правил, отсутствие комбинации — ошибка, а не fallback

- **Статус:** Accepted
- **Дата:** 2026-09-08 (оси уточнены 2026-09-09 по реальному прайсу)
- **Связанные ADR:** 0004 (снимок цены в записи)

## Контекст

Цена услуги зависит от параметров авто и задаётся правилами-комбинациями. Рассматривались способы подбора цены, когда точного правила для выбора клиента нет: молчаливый fallback на базовый тариф, поочерёдное «смягчение» опций. Любой fallback рискует показать неверную цену: потерянное правило (неполный прайс, новая комбинация без правила) выглядит как дешёвая запись, а не как дефект данных — расхождение между показанной суммой и реальным прайсом обнаружится только в споре.

## Решение

Подбор — **только точным совпадением** (услуга, радиус, тип). Для работ, цена которых зависит от параметров, прайс обязан быть полным кубом комбинаций; отсутствие правила — **ошибка конфигурации** (`PricingException`): цена не показывается, клиенту предлагается запись по телефону. Услуги без прайс-правил (доп. работы: вентиль, датчик, RunFlat-монтаж, утилизация и пр.) продаются по фиксированной цене. Показ итога и подтверждение записи используют один расчёт (НФ-4). Оси правил — услуга × радиус (R13–R21) × тип (легковые; кроссовер/внедорожник — общая колонка прайса); RunFlat/TPMS параметрами не являются — реальный прайс не дифференцирует по ним цену, это доп. работы. Зафиксировано в ФТ v0.13 (ФТ-2, ФТ-4).

## Почему (альтернативы)

- Fallback на базовую цену (ФТ v0.11): неполный прайс молча даёт минимальную цену — систематическое занижение и скрытый дефект данных.
- «Смягчение» опций: цена «ближайшего» правила теряет наценки опции, для которой правило существует; семантика вырождается в гадание по порядку сброса. С появлением реального прайса оси с опциями отпали сами: RunFlat/TPMS в прайсе — доплаты-работы, а не характеристики, влияющие на цену комбинации.
- Цена: жёсткая полнота прайса переносит ответственность на данные — админка (вне v1) должна валидировать/вести полный куб, иначе сайт перестаёт продавать комбинацию.

## Последствия

Проще: невозможна неверная цена — дефект прайса виден сразу (тест/страница), а не в споре с клиентом; расчёт однозначен, цепочки подбора нет. Сложнее: админка прайса обязана поддерживать полноту куба (валидация при заведении правил — задача будущей админки); «Грузовик» и неизвестные параметры выведены с сайта (запись по звонку), т.к. прайс-правил для них нет. Пересмотрим: если появится версионирование/матрицы прайса с частичным покрытием — пересмотреть механику неполноты.
