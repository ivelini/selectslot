# 0006. Публичный сайт: страницы на шаг записи, состояние заявки в URL и сессии

- **Статус:** Accepted
- **Дата:** 2026-09-08
- **Связанные ADR:** 0002, 0005

## Контекст
Публичный сайт — самостоятельный Livewire-сайт в монолите (ADR 0005); эталон экранов — статичный мокап `.template/` (экран = файл, поток «сначала время, потом услуги»). При переносе вёрстки в Livewire встали две развилки: строить поток одним степпер-компонентом или отдельной страницей на шаг и где держать состояние заявки между шагами — до подтверждения кода БД не пишется (ADR 0002), данные заявки должны переживать F5 и «назад» браузера.

## Решение
Каждый шаг потока записи — отдельный full-page Livewire-компонент; URL совпадают со структурой мокапа (`/`, `/booking/services`, `/booking/details`, `/booking/code`, `/my-booking/…`), переходы — `wire:navigate`. Состояние между шагами: выбор времени и услуг — в query-параметрах URL; персональные данные (имя, телефон) — POST с короткоживущим черновиком в сессии. Экраны результата (успех, «время недоступно», «код просрочен», отмена) — редирект с сессионной пометкой: идентификаторы записей в публичные URL не попадают, доступ к записи — только через верификацию телефоном и кодом (ADR 0002).

## Почему (альтернативы)
Единый степпер-компонент на `/booking` упростил бы состояние, но: теряется соответствие экран → маршрут (эталон мокапа), «назад» и глубина переходов — вручную, компонент разбухает; выбранное отсекает шаг кода (единственная точка создания записи) в чистый компонент с редиректами. Хранение всего черновика в сессии не даёт URL отражать выбор — ссылка не переживает смены устройства и «назад» по шагам; публикация ID записи в URL экрана успеха открыла бы чужие записи без аутентификации. Цена: состояние заявки распределено (query + сессия) — нужен единый черновик-DTO и серверная пересборка итоговых цен на каждом шаге.

## Последствия
Проще: перенос вёрстки мокапа постранично 1:1, шаги тестируются независимо, степпер строится обычными ссылками назад. Сложнее: соглашение о параметрах URL между шагами, восстановление выбора из query, защита от «перепрыгивания» шагов. Пересмотрим при появлении личного кабинета или SPA-дизайна одного экрана — тогда шаги съедут в степпер.
