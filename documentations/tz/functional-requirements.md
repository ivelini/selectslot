# TireSlot — функциональные требования

- **Дата:** 2026-09-08
- **Статус:** Черновик (обсуждение)
- **Версия:** 0.15

## 1. Назначение и границы

Сервис онлайн-записи на шиномонтаж: клиент выбирает услуги, параметры автомобиля и время записи; мастерская управляет записями, расписанием и справочниками через админку.

Границы v1:
- одна точка (мастерская), без мультифилиала;
- без онлайн-оплаты и предоплаты;
- каналы записи: публичный сайт (Livewire) + админка (запись по звонку);
- клиент без регистрации, идентификация по номеру телефона;
- посты (подъёмники) в бронировании не участвуют: слот — общий на мастерскую, без привязки к посту;
- SMS — только код подтверждения записи. Напоминаний, ссылок отмены и прочих SMS в v1 нет.

## 2. Роли

| Роль | Описание |
|---|---|
| Клиент | Гость, записывается через виджет. Идентифицируется по телефону |
| Оператор | Сотрудник мастерской: календарь, запись по звонку, переносы, отметки статусов, закрытие слотов, корректировка цены |
| Администратор | Управляет справочниками (услуги, цены), расписанием. Может совпадать с оператором |

## 3. Глоссарий

| Термин | Определение |
|---|---|
| Услуга | Работа из каталога. Длительность не моделируется; цена — за единицу (1 колесо/шт), количество (1–4) выбирает клиент. Работы реального прайса и доп. работы (вентиль, датчик давления, RunFlat-монтаж, утилизация и пр.) — одинаково услуги: первые с прайс-правилами, вторые — с фиксированной ценой за штуку |
| Комплекс услуг | Готовый набор из каталога (например, «Сезонный шиномонтаж»): своей цены не имеет — при выборе на сайте отмечаются входящие услуги с количеством 4. В запись комплекс не попадает: хранится только состав (услуги с количествами) |
| Параметр авто | Радиус (R13–R21) и тип (легковая/кроссовер/внедорожник; грузовик — по звонку). Влияют на цену. RunFlat/TPMS параметрами не являются: монтаж таких шин и установка датчиков — доп. работы с фиксированной ценой |
| Слот | **Внутреннее понятие сервиса:** часовое окно (12:00–13:00, 13:00–14:00 и т.д.) — единица группировки записей и закрытия времени. Хранится строкой таблицы `slots`, генерируемой планировщиком по расписанию. Клиенту не показывается |
| Время начала | Конкретное время, на которое назначена запись. Сайт предлагает только целые часы (12:00, 13:00…); админка — любое время (12:15, 12:40). Запись хранит привязку к слоту и время внутри него |
| Закрытие слота (блокировка) | Флаг на строке слота, делающий время недоступным на сайте. Может быть самостоятельным или привязанным к записи |
| Снимок записи | Параметры авто и цена, зафиксированные в записи на момент создания: строки состава хранят цену за единицу и количество. Правка прайса или авто задним числом не меняет созданные записи |
| Код подтверждения | Код из SMS: при вводе создаёт запись и далее верифицирует клиента на странице «Моя запись» для отмены. Создаёт ровно одну запись |
| Заявка на запись | Выбор клиента (услуги, параметры авто, время, имя, телефон), который он несёт по шагам сайта и передаёт целиком при подтверждении кода. Серверно до подтверждения не хранится; запись создаётся только при вводе кода — слот заранее не удерживается |
| Запись (Booking) | Бронь на конкретное время начала: клиент + услуги (с количествами) + слот + время начала + статус. Параметры авто (радиус, тип) и госномер — снимок записи (сущности «автомобиль» нет). Запись на 12:00 означает прибытие к 12:00 |

## 4. Функциональные требования

### 4.1 Справочники (администратор)

**ФТ-1. Каталог услуг.** Администратор управляет списком услуг и готовыми комплексами через админку без деплоя. У услуги: название, категория (шиномонтаж / хранение / прочее), признак активности. Комплекс — набор услуг (многие-ко-многим) с названием и признаком активности, без собственной цены. Неактивные услуги и комплексы не видны клиенту и не участвуют в записи.

**ФТ-2. Ценовые правила.** Цена за единицу услуги (1 колесо/шт) зависит от услуги, радиуса колеса (R13–R21) и типа автомобиля (легковые; кроссовер и внедорожник — общая колонка прайса). Правила — справочник в админке. Для работ, цена которых зависит от параметров, ведётся полный набор правил (все комбинации услуга/радиус/тип); подбор — по точному совпадению. Отсутствие правила для комбинации у такой услуги — ошибка конфигурации: цена не показывается, запись оформляется по телефону (ФТ-18). Услуги без прайс-правил (доп. работы) продаются по фиксированной цене. Итог строки = цена за единицу × количество. Изменение правил не требует деплоя и применяется сразу к новым записям (созданные записи не меняются — снимок).

**ФТ-3. Расписание.**

Расписание — шаблон недели: для каждого дня недели задаются часы работы или выходной; сезонные изменения — ручной правкой шаблона (периоды действия шаблонов не предусмотрены в v1). Таблицы исключений на дату нет.

Правила:
- сетка времени хранится в таблице `slots`: строки генерируются командой планировщика (каждые 15 мин) на горизонт записи (ФТ-10) по шаблону недели; генерация идемпотентна и сохраняет состояние закрытия слотов;
- отклонения от шаблона (праздник, внеплановый выходной, короткий день) — закрытием слотов из админки (ФТ-16), в т.ч. массовым действием на весь день; дни вне шаблона сайту недоступны, записи на них оператор ставит вручную из админки (строки слотов создаются при записи);
- час стал нерабочим (изменение шаблона задним числом) → строка слота удаляется, только если в ней нет записей и она не закрыта; строка с записями остаётся с предупреждением «в затрагиваемом времени N записей»; записи не отменяются и не сдвигаются автоматически — оператор разбирает их сам (обзвон, перенос);
- перерывов как отдельной сущности нет: временное закрытие внутри рабочего дня (обед, поломка) — через механизм закрытия слотов (ФТ-16).

### 4.2 Клиентская запись (сайт)

**ФТ-4. Выбор услуг и параметров.** Клиент выбирает услуги (для каждой — количество 1–4, по умолчанию 4 — сезонный комплект) или готовый комплекс (входящие услуги отмечаются, все — с количеством 4), радиус колеса (R13–R21), тип автомобиля (легковая/кроссовер/внедорожник). Радиус и тип — обязательный выбор, варианта «не знаю» нет: если параметры неизвестны клиенту или автомобиль грузовой — запись по телефону (ФТ-18).

**ФТ-5. Расчёт цены.** Система показывает клиенту итоговую цену до бронирования. Расчёт ведётся по ФТ-2.

**ФТ-6. Сетка времени.** На выбранную дату система показывает доступное время начала записи — слоты из таблицы `slots`, не закрытые оператором (см. ФТ-16), с учётом ограничений ФТ-10. Количество записей в слоте не ограничивает доступность: лимита на час нет — в одном слоте может быть несколько записей (например, 12:00 и 12:30). Закрытый слот отображается как недоступное время.

**ФТ-7. Запрос кода.** Клиент выбирает время и вводит: имя, телефон, госномер (необязателен). Система проверяет доступность времени (слот существует и не закрыт) и отправляет SMS с кодом. Запись при этом не создаётся и слот не удерживается; заявка серверно не сохраняется — при подтверждении клиент передаёт актуальный выбор. Изменение услуг, параметров или времени после отправки кода не требует нового кода (одна SMS на цикл записи).

**ФТ-8. Подтверждение и создание записи.** Ввод кода создаёт запись из актуального выбора, переданного клиентом при подтверждении, с временем начала = выбранному часу (12:00), сразу в статусе `confirmed` — слот бронируется только после подтверждения. Создание атомарно: блокировка строки слота, слот не закрыт → запись создана; закрыт/удалён → отказ «время недоступно, выберите другое». Цена пересчитывается сервером по актуальным правилам (ФТ-2) из переданного выбора — показ итога и создание записи используют один расчёт, сумма клиентом не передаётся. Код создаёт ровно одну запись; повторная отправка кода возможна.

**ФТ-9. Срок действия кода.** Неподтверждённый код действует ограниченное время (по умолчанию 15 мин — параметр); просроченные коды удаляются кроном. Запись при этом не создана — слот свободен. После создания записи код продолжает служить верификатором отмены (ФТ-14), пока запись активна.

**ФТ-10. Ограничения записи.** Минимальное время до начала (по умолчанию 1 ч) и горизонт записи (по умолчанию 30 дней) — параметры конфигурации. Вне этих границ время не предлагается.

**ФТ-11. Детали записи.** После создания записи клиент видит детали: дата, время начала (прибыть к этому времени), адрес, состав услуг, итоговая цена, телефон мастерской.

### 4.3 Статусная машина

**ФТ-12. Статусы и переходы.**

| Статус | Значение | Допустимые переходы | Кто переводит |
|---|---|---|---|
| `confirmed` | Запись создана, ждёт клиента | → `arrived`, → `no_show`, → `cancelled` | оператор, клиент (только отмена, см. ФТ-14) |
| `arrived` | Клиент приехал, работы ведутся | → `done` | оператор |
| `done` | Завершена | — (конечный) | |
| `cancelled` | Отменена (хранится причина) | — (конечный) | |
| `no_show` | Клиент не пришёл | — (конечный) | оператор |

Переводы, не перечисленные в таблице, система отклоняет. Статусная машина — единый класс, используемый и виджетом, и админкой.

**ФТ-13. Неявка (no-show).** Оператор отмечает `no_show` по подтверждённой записи, если клиент не пришёл к времени начала. В v1 — только ручная отметка, без автоматических санкций; счётчик неявок хранится в карточке клиента.

**ФТ-14. Отмена клиентом.** Клиент может отменить `confirmed`-запись на сайте: вводит телефон и код из SMS, видит активные записи и отменяет. Без ограничений более чем за 2 ч до начала; менее чем за 2 ч — отмена недоступна, только через звонок оператору. Порог (2 ч) — параметр.

**ФТ-15. Отмена оператором.** Оператор может отменить запись в любом статусе до `done` с указанием причины. Если к записи привязано закрытие слота — оно снимается.

### 4.4 Закрытие слотов

**ФТ-16. Единый механизм блокировки.** Закрытие слота — флаг на строке `slots` (причина + привязка к записи). Два способа:
- напрямую в календаре: оператор закрывает слот без записи (поломка, перерыв, приём вне учёта) с указанием причины; снимается оператором вручную. Есть массовое действие — закрыть/открыть все слоты дня разом (праздник, внеплановый выходной);
- чекбоксом «Закрыть слот» на записи: слот помечается закрытым и привязывается к записи. При переносе записи флаг следует за записью (старый слот открывается, новый закрывается); при отмене записи — снимается.

Если строка слота не существует (время вне расписания) — она создаётся при записи; с чекбоксом — сразу закрытой.

Закрытие слота не отменяет существующие записи в нём — они остаются, слот лишь перестаёт предлагаться на сайте (время слота становится недоступным).

### 4.5 Админка (оператор)

**ФТ-17. Календарь дня.** Админка показывает записи на выбранную дату, сгруппированные по часовым слотам: время начала, состав услуг, клиент, телефон, статус (с цветовой индикацией). Закрытые слоты отмечены отдельно. В одном слоте отображаются все его записи (например, 12:00 и 12:30).

**ФТ-18. Запись по звонку.** Оператор создаёт запись из админки по тем же правилам расчёта цены, что и виджет (ФТ-4–ФТ-5), с любым временем начала (12:15, 12:40). SMS-подтверждение не требуется — запись сразу в `confirmed`. Если слот для этого часа отсутствует — он создаётся. При создании можно поставить чекбокс «Закрыть слот» (ФТ-16). Поиск/создание клиента по телефону; при повторной записи подставляются госномер и параметры из последней записи клиента.

**ФТ-19. Корректировка цены записи.** Оператор может в админке изменить цену записи: цены строк состава и итоговую сумму (ручная скидка/наценка по договорённости). Правка прайса (ФТ-2) задним числом не меняет созданные записи — в записи хранится снимок.

**ФТ-20. Перенос записи.** Оператор переносит запись на другое время начала (другой слот/время). Привязанное закрытие слота следует за записью (ФТ-16). О переносе оператор сообщает клиенту сам (звонок); SMS в v1 нет.

**ФТ-21. Отметки статусов.** Оператор отмечает `arrived` и `done` (ФТ-12), `no_show` (ФТ-13).

**ФТ-22. Карточка клиента.** По телефону доступны: имя, история записей (с госномером и параметрами — снимки записей), счётчик неявок.

### 4.6 SMS-подтверждение

**ФТ-23. Код подтверждения.** Клиенту отправляется SMS с кодом при запросе записи (ФТ-7); повторная отправка возможна (например, код не пришёл или истёк). Код не привязан к конкретному составу заявки: ввод кода подтверждает выбор, переданный в этот момент (ФТ-8). Код создаёт ровно одну запись и затем верифицирует клиента на странице «Моя запись» для отмены (ФТ-14), пока запись активна.

**ФТ-24. Отказоустойчивость SMS.** Отправка через очередь с ретраями; сбой SMS-провайдера не блокирует создание и подтверждение брони.

## 5. Нефункциональные требования

| Код | Требование | Приоритет |
|---|---|---|
| НФ-1 | Атомарность пары «слот не закрыт» + создание записи при подтверждении кода (блокировка строки слота, `SELECT … FOR UPDATE`): гонка между подтверждением клиента и закрытием слота оператором невозможна; двойное создание одной записи исключено (код одноразовый, `idempotency_key`) | Критический |
| НФ-2 | Показ сетки времени и создание резерва укладываются в целевое время отклика даже в сезонный пик (октябрь/апрель) | Высокий |
| НФ-3 | Справочники и расписание конфигурируются из админки без деплоя | Высокий |
| НФ-4 | Логика записи и закрытия слотов — в одной точке приложения; все каналы записи (сайт, админка, будущие) используют её | Высокий |
| НФ-5 | Сбой доставки SMS не влияет на консистентность броней (ФТ-24) | Средний |

## 6. Вне рамок v1

- Онлайн-оплата и предоплата (интерфейс заложить, не реализовывать)
- Мультифилиал / сеть точек
- Посты как ресурс бронирования и привязка записей к постам (внутренний учёт)
- Напоминания клиенту (SMS/мессенджеры), SMS-уведомления о переносе
- Телеграм-бот и прочие каналы записи
- Личный кабинет клиента
- Онлайн-чат с мастерской, интеграция с картами (2ГИС/Яндекс)
- Отчёты и аналитика (загрузка по слотам, выручка по услугам)

## 7. Параметры конфигурации (значения по умолчанию, уточняются с заказчиком)

| Параметр | Значение по умолчанию |
|---|---|
| Срок действия кода подтверждения | 15 мин |
| Порог свободной отмены клиентом | 2 ч до начала |
| Минимальное время записи до начала | 1 ч |
