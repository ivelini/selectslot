# Создание записи: заявка → код → подтверждение

> Sources: TireSlot ФТ v0.11, 2026-09-08; db-schema v0.8, 2026-09-08; ADR 0002, 2026-09-04; Рефакторинг доменного слоя, 2026-09-09
> Raw: [ФТ v0.11](../../raw/domain/2026-09-08-functional-requirements.md); [db-schema v0.8](../../raw/domain/2026-09-08-db-schema.md); [ADR 0002](../../raw/architecture/2026-09-04-0002-zapis-pri-podtverzhdenii-koda.md); [Рефакторинг слоёв и конвенций](../../raw/architecture/2026-09-09-refaktoring-sloev-i-konventsii.md)

## Overview

Запись создаётся **только при подтверждении SMS-кода** — сразу в статусе `confirmed` (ADR 0002). Заявка до подтверждения **не хранится**: клиент несёт выбор по шагам сайта и передаёт актуальный при вводе кода — поэтому изменение услуг/времени после запроса кода не перевыпускает код (одна SMS на цикл записи, каждая SMS — расходы). Слот не удерживается: удерживать нечего — лимита записей в часе нет (ADR 0003), а промежуточный статус дал бы висящие записи в календаре оператора и крон истечения без защиты времени. Из админки (по звонку) запись создаётся сразу, без кода.

## Клиентский поток (сайт)

1. **Выбор времени и услуг** — см. [pricing](pricing.md) и [slot-grid](slot-grid.md). Сайт предлагает только целые часы начала (12:00, 13:00…).
2. **ФТ-7, запрос кода** (шаг «Данные», реализован): клиент вводит имя, телефон, госномер (необязателен). Система проверяет доступность времени (слот существует и не закрыт) и отправляет SMS с кодом. В `booking_codes` сохраняются только `phone` (канон «7XXXXXXXXXX»), `code_hash` (sha256 кода + ключ приложения); заявка не сохраняется. Контакты клиента — сессионный черновик `booking_draft` (ADR 0006). Отправка — `SendBookingCodeSms` через очередь (ФТ-24): контракт SmsSender, dev-драйвер пишет в лог. Запись не создаётся.
3. **ФТ-8, подтверждение** (шаг «Код», реализован): ввод кода атомарно создаёт запись из актуального выбора, переданного клиентом при подтверждении. `CreateBookingAction::handle` (App\Actions) в транзакции блокирует строку слота (`SELECT … FOR UPDATE`, НФ-1): слот открыт → запись `confirmed` со снимком (radius/car_type/plate — сущности «автомобиль» нет, ADR 0009); закрыт/удалён → SlotUnavailableException, экран unavailable. Цена — серверный пересчёт по правилам ([pricing](pricing.md)), сумма клиентом не передаётся. Одноразовость кода — атомарный `used_at`; повторный submit использованного кода возвращает существующую запись через `Booking::forCode(code)` (Used → success); экраны результата — редиректы с flash-пометкой (ADR 0006), черновик очищается.
4. **ФТ-11, детали**: после создания клиент видит дату, время начала (прибыть к этому времени), адрес, состав, итог, телефон мастерской.
5. Код продолжает служить верификатором отмены на «Моей записи» — `code_hash` переносится в `bookings` — см. [booking-statuses](booking-statuses.md).

## Код подтверждения

- TTL — по `created_at` + параметр `reservation_timeout_min` (15 мин; чтение — `Setting::get(SettingKeyEnum::ReservationTimeoutMin)`), поля `expires_at` нет; просроченные неиспользованные коды удаляются кроном (использованные не удаляются — на них ссылаются записи). Запись при этом не создана — слот свободен.
- Повторная отправка кода возможна (новый код на телефон; заявки не перевыпускает — её нет).
- SMS — только код; напоминаний и ссылок отмены в v1 нет. Отправка через очередь с ретраями: сбой провайдера не блокирует бронирование (ФТ-24, НФ-5).

## Ограничения записи (ФТ-10)

Параметры конфигурации (словарь ключей и дефолтов — `SettingKeyEnum`, чтение — `Setting::get`): `min_lead_time_h` (1 ч до начала) и `booking_horizon_days` (30 дней). Вне границ время не предлагается.

## Канал админки (запись по звонку)

Оператор создаёт запись по тем же правилам расчёта цены с **любым** временем начала (12:15, 12:40) — сразу `confirmed`, без SMS. Если строки слота для часа нет — создаётся. Опционально чекбокс «Закрыть слот» (привязка закрытия к записи). Поиск/создание клиента по телефону; повторная запись подставляет сохранённые авто и параметры.

## Порядок шагов на сайте

Мокап фиксирует поток «сначала время, потом услуги» — решение пользователя, не переоткрывать; ФТ описывает выбор услуг раньше времени. Это расхождение источников: см. [public-site-mockup](../frontend/public-site-mockup.md).
