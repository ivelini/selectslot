# Цены: прайс-правила, расчёт, снимок в записи

> Sources: TireSlot ФТ v0.14, 2026-09-09; db-schema v0.10, 2026-09-09; ADR 0004, 2026-09-04; ADR 0007, 2026-09-08 (оси уточнены 2026-09-09); реализация CalculatePriceAction, 2026-09-08/09; Рефакторинг доменного слоя, 2026-09-09
> Raw: [ФТ v0.13](../../raw/domain/2026-09-09-functional-requirements.md); [db-schema v0.9](../../raw/domain/2026-09-09-db-schema.md); [ADR 0004](../../raw/architecture/2026-09-04-0004-snimok-tseny-v-zapisi.md); [Политика прайса реализована](../../raw/domain/2026-09-08-prajs-politika-podbora-realizovana.md); [Реальный прайс: оси и количество](../../raw/domain/2026-09-09-realnyi-prajs-osi-kolichestvo.md)

## Overview

Цена услуги — **за единицу (1 колесо/шт)** — зависит от услуги, радиуса колеса и типа авто; итог строки = цена × количество (1–4). Расчёт ведётся по единым правилам для всех каналов записи (виджет и админка) и показывается клиенту до бронирования. Запись хранит **снимок** параметров и цен на момент создания (ADR 0004) — прайс, изменённый задним числом, на созданные записи не влияет.

## Каталог услуг (ФТ-1)

Услуги: название, категория (`tire` / `storage` / `other`), признак активности, базовая цена. Неактивные не видны клиенту и не участвуют в записи. Работы реального прайса (снятие/установка, демонтаж, монтаж, балансировка, комплекс) и доп. работы (вентиль, датчик давления, RunFlat-монтаж, смазка ступицы, утилизация) — одинаково услуги: первые с прайс-правилами, вторые — с фиксированной ценой. Комплектные строки прайса («4 колеса», «при покупке −20 %») не заводятся — комплект закрывается количеством. Готовые комплексы-наборы (`complex_services`, ADR 0008) — без собственной цены: при выборе отмечают входящие услуги ×4, в запись попадает состав.

## Прайс-правила (ФТ-2, ADR 0007)

Правило — комбинация (услуга, радиус R13–R21 поштучно, тип) с ценой за единицу. Ценовые колонки прайса: «легковые» (passenger) и «внедорожная» (crossover и suv — общая цена); прайс-группы радиусов (R12–15 / R16–17 / R18–19 / R20–21) развёрнуты на радиусы. Политика подбора (ADR 0007, ФТ v0.13):

- у услуги **0 правил** (доп. работы) → фиксированная цена `base_price`;
- иначе подбор — **только точным совпадением** (услуга, радиус, тип): для работ прайс обязан быть полным кубом комбинаций;
- комбинации нет при наличии правил у услуги → **PricingException** — ошибка конфигурации: цена не показывается, клиенту предлагается запись по телефону (не молчаливая база — fallback давал бы заниженную цену при потерянном правиле).

RunFlat/TPMS **не параметры**: реальный прайс не дифференцирует по ним цену — это доп. работы (+100 ₽). Параметры клиента: радиус и тип — обязательный выбор, варианта «не знаю» нет (ФТ-4 v0.13); грузовые авто — запись по звонку (ФТ-18). Изменение правил применяется сразу к новым записям.

**Реализация:** `App\Actions\CalculatePriceAction::handle(услуги, VehicleParams, quantities[id=>1..4])` — единый расчёт для показа и подтверждения (НФ-4); строки {service, unit_price, quantity, price=unit×qty}, total. `VehicleParams` = radius + carType (App\ValueObjects); `WheelRadiusEnum` R13–R21; типы сайта — `CarTypeEnum::bookable()`. Демо-сид: полный куб по реальному прайсу — **135 правил** (5 работ × 9 радиусов × 3 типа): снятие/установка лёгк. R12–15 = 150 ₽, R20–21 = 380 ₽, внед. R16–17 = 300 ₽ и т.д.

## Снимок в записи (ADR 0004, ФТ-19)

При создании записи фиксируются: радиус, тип авто, `total_price`, строки состава (`booking_services.price` — за единицу, `quantity`). Заявка до подтверждения не хранится: при вводе кода цена пересчитывается сервером по актуальным правилам из выбора клиента и фиксируется в записи — показ итога и создание используют один расчёт (ФТ-8). Оператор может скорректировать цены строк и итог в админке (ручная скидка/наценка по договорённости). Пересмотр: если появится версионирование прайса — снимок заменится ссылкой на версию.
