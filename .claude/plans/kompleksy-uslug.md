# Пакеты услуг (комплексы): complex_services + авто-выбор состава

- **Дата:** 2026-09-09
- **Статус:** согласован, реализация

## Цель

Готовые комплексы из каталога (справочник): клиент выбирает «Сезонный шиномонтаж» — его услуги автоматически отмечаются на шаге «Услуги» с количеством 4.

## Решения (согласованы)

- Пакет — набор без собственной цены: итог = сумма входящих услуг × количества (пакет не продаётся).
- Клик по пакету: состав полон И все его услуги = 4 → снять услуги пакета (вне-пакетные не трогаются); иначе → **привести к комплекту ×4**: недостающие добавить, **все** услуги пакета установить в 4 (уже выбранные переустанавливаются, а не сохраняют qty).
- Состояние пакета (дериват выбора): выбран / частично / не выбран; в URL не пишется.
- Снимок, URL, расчёт, подтверждение не знают о пакетах: сохраняются только услуги с количествами.
- Демо-пакет «Сезонный шиномонтаж» = Снятие и установка колёс + Демонтаж колёс + Монтаж колёс + Балансировка колёс.

## Задачи

1. Миграция (db-schema v0.10): `complex_services` (name, is_active) + `complex_service_item` (complex_service_id, service_id; unique-пара); модели `App\Models\Service\ComplexService`, связь многие-ко-многим с Service.
2. `ServicesStepPage::toggleComplex(id)` + состояние пакетов в render (full/partial/none); блок «Комплексы» в view (карточки-чекбоксы, partial-стиль).
3. Сид: пакет «Сезонный шиномонтаж» в CatalogSeeder (после услуг; updateOrCreate + sync).
4. Мокап services.html: блок «Комплексы» + сценарий (пакет выбран, 4 услуги ×4; R16 кроссовер: 1 200 + 800 + 800 + 1 200 = 4 000 ₽); CSS карточек пакетов (мокап + public).
5. Документация: ФТ v0.14 (комплексы в справочниках и ФТ-4; пакет в запись не попадает), db-schema v0.10; вики — после ответа на вопрос.
